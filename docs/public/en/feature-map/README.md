# Lineage 2 feature map

A feature-by-feature map of Lineage 2 server mechanics for three versions of the game — Interlude, High Five and Essence — built from the source code of the Mobius trees and of other open-source server builds. For every feature the map gives a short description, which versions have it, which builds show it, where to start reading the code, which network packets belong to it, and how other projects fixed bugs in it.

## How the map is used in the nx-l2 refactor

`nx-l2` splits the imported Mobius code into a shared `engine/` and per-version modules `chronicles/<version>`. The map answers three questions for every feature:

- **Where does it belong?** The `Shared` field: `engine` goes to the shared engine, `partial` goes to a shared module with extension points for the versions that differ, `chronicle-only` stays in its `chronicles/<version>` module.
- **What do the other versions and builds do?** The `Present` / `Difference` columns and the entry points show the reference implementations (`mobius-il`, `mobius-ess`, `acis`, `l2j-server`, …) to compare with the High Five baseline in `nx-l2`.
- **How were bugs in it fixed elsewhere?** `Known fixes` lists up to three telling commits from the history of the public builds, so a bug in a feature can be checked against earlier fixes.

The map is a navigation aid, not detailed documentation: it points to the files and states the essence of the feature in a few lines.

## Reading a block

Every feature is one block in the file of its domain (`<domain>.md`):

````markdown
### mail.send — Send mail

ID: `mail.send` · Shared: **partial (HF+Ess)**

Short description of the feature.
Sub-features: attachments · COD · …

| Chronicle | Present | Builds (evidence) | Difference |
| --------- | ------- | ----------------- | ---------- |
| Interlude | no      | mobius-il, acis   | …          |
| High Five | yes     | nx-l2, l2j-server | baseline   |
| Essence   | differs | mobius-ess        | …          |

Entry points

- `nx-l2:chronicles/high-five/…/RequestSendPost.java`
- `mobius-ess:java/org/l2jmobius/gameserver/…/RequestSendPost.java`

Packets

| Chronicle | Client → server           | Server → client           |
| --------- | ------------------------- | ------------------------- |
| High Five | `RequestSendPost` `D0:66` | `ExReplySentPost` `FE:AD` |

Notes: …

Known fixes: `l2j-server@663b9d70` (2010-01-22, concurrency) — …
````

| Field | Meaning |
| ----- | ------- |
| ID | Stable identifier `<domain>.<feature>` in kebab-case. It never changes when a feature is moved or renamed in the text. |
| Shared | Verdict by game version, not by build. `engine` — the feature is in all three versions with the same logic: a candidate for the shared engine. `partial` — a common core with differences per version (listed in `Difference`): a shared module with extension points. A feature that exists in exactly two versions is always `partial` and names them: `partial (HF+Ess)`, `partial (IL+HF)`, `partial (IL+Ess)`. `chronicle-only` — exists in one version only. Differences between builds of the same version do not change the verdict; they are written in `Notes`. |
| Present | Per version: `yes` — present, same as the baseline; `no` — absent; `differs` — present with differences (see `Difference`), or a Mobius custom feature that exists in the tree but is switched off by default. |
| Builds (evidence) | The builds in which the feature was checked, by build key (see the table below). A key in parentheses or a remark after it limits the evidence to a part of the build (for example `mobius-il (custom backport)`). |
| Entry points | Files to start reading, as `<build-key>:<path>`; `nx-l2:chronicles/high-five/…` are paths in this repository. Braces `{A,B}.java` list sibling files; `**/Name.java` means the file was found by name only. |
| Packets | Packet name and opcode per version, client → server and server → client. `XX` is a one-byte opcode in hex; `XX:YYYY` is an extended packet: `D0` (client → server) or `FE` (server → client) followed by the sub-opcode, with four digits when the sub-opcode does not fit in a byte (`FE:0133`). Names are the Mobius class names, or the enum constants where a packet has no class. For packets with a mask (`UserInfo`, `CharInfo`, `NpcInfo`, …) the mask bits that belong to the feature are listed. Opcodes come from the packet catalogue of each version: Interlude — the Mobius Interlude protocol, High Five — protocol 267/273, Essence — the Mobius Essence 09.2 RoseVain protocol. |
| Notes | Remarks on the builds of the same version, open questions, the reason for an unusual verdict. |
| Known fixes | Up to three telling bug-fix commits from the history of the public builds: `<build-key>@<commit>` (date, class) — subject. Classes: `exploit-dupe`, `crash-npe`, `concurrency`, `missing-check`, `wrong-formula-value`, `retail-like`, `other`. The class is a keyword heuristic on the commit text. |
